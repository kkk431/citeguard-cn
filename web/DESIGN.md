# CiteGuard-CN Web · 设计与接口说明（v0.1）

> 目标：做一个「学术编辑部工具」，不是「AI 生成器」。第一眼看上去像一本严谨的期刊/数据库产品：安静、克制、信息密度高、没有 AI 味。

## 1. 产品定位

**引证卫士 CiteGuard-CN** —— 中文论文引文体检工作台。

- 用户：写毕业论文/课程论文/投稿的研究生、导师、期刊编辑。
- 一句话：上传论文，3 分钟得到「哪条引用是假的、哪条张冠李戴、哪条格式不合新国标」的逐条报告。
- 主形态：Web 工作台；内核：多阶段核验工作流。
- 不要出现：聊天框、对话气泡、「AI 助手」人设、紫色渐变、玻璃拟态、emoji 堆砌。

## 2. 视觉系统（Design Tokens）

### 2.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#F7F6F3` | 页面底色（暖白纸感） |
| `--surface` | `#FFFFFF` | 卡片/面板 |
| `--ink` | `#161616` | 主文字 |
| `--ink-2` | `#4B4B4B` | 次文字 |
| `--muted` | `#8A8A8A` | 说明文字 |
| `--line` | `#E4E1DA` | 分隔线/边框 |
| `--accent` | `#A63D2F` | 主强调色（朱砂红，按钮/重点数字） |
| `--accent-soft` | `#F3E7E3` | 强调色浅底 |
| `--ok` | `#1F7A4D` | 真实/一致 |
| `--warn` | `#B26A00` | 元数据偏差 |
| `--bad` | `#B3261E` | 疑似虚构/错配 |
| `--unknown` | `#6B6B6B` | 无法核验 |

状态色只用于状态，不用于装饰。强调色只用于「主按钮 / 关键数字 / 当前选中」。

### 2.2 字体

- 中文标题：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", serif`（衬线，学术感）
- 正文/界面：`"Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`
- 数字/代码：`"IBM Plex Mono", "JetBrains Mono", monospace`
- 字号：12/13/14/16/20/28/40；正文 14–15px，行高 1.7；标题字重 600，不要 800。

### 2.3 间距与形状

- 间距基数 4px；常用 8/12/16/24/32/48/64。
- 圆角：卡片 10px，按钮 8px，pill 999px；**不要大圆角+大阴影的“AI 卡片”**。
- 阴影：仅 `0 1px 0 rgba(0,0,0,.03)` 或 1px 边框；悬浮态用边框加深，不用发光。
- 布局：最大宽 1200px，居中；顶部导航 64px；报告页左侧 220px 目录（桌面端），移动端折叠。

## 3. 页面

### 3.1 `/` 首页

结构：
1. 顶部导航：左侧 wordmark「引证卫士 / CiteGuard」，右侧 `工作台` `评测` `关于` `GitHub`。
2. Hero：左侧大标题（衬线，2 行）「给中文论文做一次引文体检」；副标题 1 行；右侧一张「报告摘要卡」的静态预览（4 个数字 + 3 条状态条）。
3. 上传区：大拖拽区（虚线边框，拖入高亮），支持 PDF/Word/txt；下方「或粘贴文本」「用示例论文试试」；主按钮「开始体检」。
4. 最近任务：表格（文件名 / 时间 / 状态 / 风险指数 / 查看），空态文案。
5. 三步说明：`解析引文 → 多源核验 → 规则检查`，横向排列，不要图标堆砌。

交互：拖拽、选择文件、粘贴文本切换、上传后跳 `/report/{job_id}` 并显示进度。

### 3.2 `/report/{job_id}` 报告页

- 顶部摘要条（sticky）：文件名、生成时间、`导出 HTML / Markdown / JSON`、`重新检测`。
- 4 个统计卡：参考文献数、真实一致、元数据偏差、疑似虚构/错配、新国标合规均分。数字大、说明小。
- 风险条：一条水平堆叠条（绿/黄/红），下方小字图例。
- 工具栏：搜索框（题名/作者）、状态筛选 chips（全部 / 真实 / 偏差 / 虚构 / 无法核验）、排序（按序号 / 风险 / 合规分）、视图切换（卡片 / 表格）。
- 引用列表：每条一张卡
  - 左侧色条（状态色）+ 序号；
  - 标题（衬线 16px）、作者·年·来源；
  - 状态 pill + 合规分；
  - 原始引文（等宽小字，可复制）；
  - 证据行：`title_sim` / `year_match` / `author_match` + 「查看证据」外链；
  - 问题列表（error/warning/info 三色）；
  - 展开/收起「修复建议」。
- 空态/加载态：骨架卡片 3 张；错误态给「重试」。

交互：筛选/搜索/排序即时生效（前端过滤，数据一次注入）；键盘 `/` 聚焦搜索；`Esc` 清空；复制按钮 toast。

### 3.3 `/benchmark` 评测页

- 标题 + 一段说明（数据从哪来、怎么构造）。
- 指标卡：macro-F1、accuracy、支持度 F1、平均耗时。
- 混淆矩阵（3×3，纯 CSS grid 或 canvas）。
- 对比表：ours / DeepSeek API / zero-shot / RefChecker（有数据才显示）。
- 消融表：去掉 normalization / reranker / 规则引擎后的指标。
- 如果 `data/citebench_cn/results.json` 不存在，显示「评测尚未运行」的空态，不要报错。

### 3.4 `/about` 关于页

- 架构图（用 HTML/CSS 画，不要贴图片）：输入 → 解析 → 多源核验 → 支持度 → 规则引擎 → 报告；每块标「自研 / 开源组件 + 许可证」。
- 开源资源表：名称、版本、许可证、用途。
- 路线图：三列（现在 / 下一步 / 未来）。
- 链接：GitHub、数据卡、许可证。

## 4. 文案规范（去 AI 味）

- 不用「智能」「赋能」「一站式」「无缝」「极致」「革命性」。
- 不用感叹号；不用「让我们」；不用「请注意」。
- 数字给出来源；不确定就写「无法核验」。
- 状态用词：`真实一致` / `元数据偏差` / `疑似虚构或错配` / `无法核验`。
- 空态：`还没有任务。上传一篇论文，或先用示例论文试试。`
- 错误：`解析失败：PDF 可能是扫描件。请先 OCR，或粘贴文本。`

## 5. API 契约（后端已按此实现）

```
POST /api/analyze            multipart: file=@paper.pdf  或  form: text=...
  → 202 {"job_id": "..."}
GET  /api/jobs/{job_id}      → {"id","status","progress","stage","filename","error","created_at"}
GET  /api/report/{job_id}    → report JSON（见 build_report 结构）
GET  /api/report/{job_id}/export?format=html|md|json → 文件
GET  /api/benchmark          → {"available": bool, ...}
GET  /api/health             → {"ok": true}
```

页面路由：`/`、`/report/{job_id}`、`/benchmark`、`/about`。

## 6. 技术栈

- 后端：FastAPI + Uvicorn + Jinja2（MIT）。
- 前端：Jinja2 模板 + 自定义 CSS（无 Tailwind 运行时依赖，避免 CDN 不稳定）+ 原生 JS。
- 字体：本地系统字体优先；不引外网字体（离线可跑）。
- 图标：内联 SVG（16/20px，stroke 1.5），不用 icon font。
