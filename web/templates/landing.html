Why CiteGuard

查重、文献管理、通用大模型，
都替代不了「核验」。

它们回答的是「像不像」「放哪儿」「怎么说」，而引文核验要回答的是「这条引用到底成不成立」。

Question 01

它真的存在吗？

OpenAlex、Crossref、arXiv、DOI 与本地题录库交叉核验。查不到会如实标成「未核验」，不会说成「造假」。

Question 02

它撑得住这句话吗？

两段式判定：先看文献是否存在，再判摘要是否支持正文。覆盖审计会主动把「部分支持」降级，理由必须能落回原文。

Workflow

一次体检，三步闭环。

从「找出问题」到「改完复检」，不用在五个工具之间来回搬文献。

上传

PDF / Word / TXT / MD 都行。自动拆出正文、参考文献、正文引注与图表标签。

PDFDOCX扫描件 OCR批量

核验

真实性、支持度、国标格式三条线并行；可选图表结论抽检。每条结论都带证据和理由。

多源核验两段式判官规则引擎图表 VL

交付与复检

报告、批注 PDF、RIS / EndNote / BibTeX 导出；改完再传一次，自动对比哪些问题真的修好了。

批注 PDF9 种导出分诊Diff 复检
Open & honest

把方法摊开，才敢让你信。

代码、评测集、模型适配器、证据索引全部开放；同时把「不做什么」也写清楚。

  • ✓
    Apache-2.0 代码，评测集与 LoRA 适配器一起开放

    GitHub 仓库、ClaimSupport-CN 300、CiteBench-CN v2 500、Qwen3-1.7B adapter。

  • ✓
    本地可跑，也能离线

    Docker 一条命令起服务；断网时只做本地解析、规则检查与本地库核验。

  • ✓
    每条结论都带证据

    原文页码、证据原句、判定理由、低置信度提示；报告可导出、可批注、可复检。

  • ✓
    接口可复用

    HTTP API、批量接口、SSE 进度、Python 客户端与浏览器扩展，方便接进自己的工作流。

  • ✕
    不训练基础大模型

    用开源模型 + 规则 + 检索组合；模型可换，证据链不换。

  • ✕
    不替代人工终审

    低置信度会标出来，图表核验只做第一道筛查，不替人读图下最终结论。

  • ✕
    不把「查不到」说成「造假」

    未核验、数据源失败、Unknown 单独列出，原因写清楚。
