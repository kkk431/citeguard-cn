# 下一步优化路线（冲国一）

> 本文件只写“还没做到的事”和验收口径，不写宣传语。当前版本 0.9.82。

## 现在站得住的部分

- 核验链路：真实已发表语料 409 条引用，0 条 Major（无“严重不符”判定）；22 篇 PDF 解析 529 条、clean 1.0。
- 解析盲测：第五次预注册盲测 3 篇全新 PDF，Qwen3-2505 / DeepSeek-R1 / Mixtral，条目健康率 100% / 96.7% / 100%，全部过 95% 阈值；协议与结果在 `data/experiments/blind_test5*`、`docs/blind_test_results.md` §14。
- 小模型：Qwen3-1.7B LoRA 支持度四分类，test 60 条 macro-F1 0.9721 / acc 0.9667（基座零样本 0.4935 / 0.4833）；adapter、训练脚本、模型卡均已开源。
- 数据集：ClaimSupport-CN 300 条（构造标签，非人工标注），统一复跑 0.9841 / 0.9833。
- 工程：506 tests、`verify_artifacts` 137/137、CI 绿、Docker 健康检查通过、SSE 进度、Python SDK、浏览器扩展、Word 任务窗格（HTTPS 已通，真机插入待人工点一次）。

## 还没做到的

1. **没有真人盲标**：300 条标签由构造规则决定；`human_review_40.csv` 只是空白模板，不能当人审证据。
2. **Word 任务窗格没完成真机交互验证**：HTTPS、证书、dev 注册、Word 启动都实测了；任务窗格需要人工在「插入 → 我的添加项」点一次，自动化未完成。
3. **解析盲测样本仍小**：每次 3 篇、共 5 次；健康率是启发式指标（长度/小写词/逗号数），不是语义正确率。
4. **材料没同步**：PPT / 提交包仍是 0.9.77 口径，未跟 0.9.82（506 tests、盲测 5、Word、SDK）对齐。

## 优化优先级（按“评委能验证”排序）

### P0：真人盲标（最缺的证据）

- 目标：30–50 条真实中文引用（含支持/部分/矛盾/无证据），请 3 位同学独立盲标。
- 交付：协议（先写死标签定义与抽检规则）、原始表、一致性 κ、分歧清单；结果无论好坏照实公开。
- 验收：`docs/human_review_report.md` + `data/experiments/human_review_*.json`；报告与 PPT 引用真实数字。
- 边界：不把“构造标签”说成“人工标注”；没有真人数据就写“未开展”。

### P1：解析泛化再加一层

- 目标：再选 3 篇**未参与前五次盲测**的 PDF（中英混合、含书籍/标准/专利条目），预注册后只跑一次。
- 验收：健康率 ≥95% 才宣布通过；失败就写失败原因，不调参重跑。
- 同时补：版面选择器的单元测试（PaLM 163 vs 裸文本 53 的选路）。

### P2：Word 真机 + 生态截图

- 目标：在 Word 里手动插入任务窗格，选中一句话→核验→截图/录 10 秒 GIF。
- 验收：`docs/word_addin_verified.md` 附截图与版本号；未验证前 README 保持“预览版”。

### P3：性能与并发实测

- 目标：1000 条引用的长文档冷启动与并发（`VERIFY_WORKERS` / `SUPPORT_WORKERS` 4/4）耗时表；SSE 进度在真实任务里的首事件延迟。
- 验收：`docs/performance.md` 增加长文档表，命令可复现。

### P4：材料同步

- 目标：技术报告、PPT、提交包统一到 0.9.82 口径（506 tests、盲测 5、Word、SDK、SSE）。
- 验收：报告 10 页内、PPT 18 页内，所有数字能从 `data/experiments/*.json` 追到。

## 不做什么

- 不做演示视频（除非用户明确要求）。
- 不伪造用户反馈、不把构造集说成人审、不把“健康率”说成语义准确率。
