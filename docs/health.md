# 引用健康画像（Citation Health Profile）

报告总览里的「引用健康画像」把一篇论文的引用质量压缩成 **0–100 分 + A–E 等级**，
并给出「最该先修」的 3 条以内建议。它是规则加权分，不是期刊标准，也不是同行评审结论。

实现：`src/citeguard/health.py` 的 `compute_health(report)`；报告 JSON 的 `health` 字段；
网页端由 `web/static/js/report.js` 的 `renderHealth()` 渲染。

## 五个维度

| 维度 | 权重 | 数据来源 | 打分方式 |
| --- | --- | --- | --- |
| 真实性 | 25 | `references[*].status`（逐条核验结果） | Exact 100 / Minor 75 / Unverified 35 / Unknown 35 / Major 0，按条数加权平均 |
| 支持度 | 25 | `support.summary`（两段式判定的第二段） | support 100 / partial 60 / contradict 0 / no_evidence 15，按已判定条数平均 |
| 相关性 | 20 | `citations.coverage.ratio` | 正文引用到的参考文献比例（0–1）×100 |
| 覆盖 | 15 | `citation_consistency`（数字编号） | 1 − 缺失编号数 / 编号总数；有编号倒序时附加说明 |
| 规范性 | 15 | `stats.avg_compliance` | 逐条 GB/T 7714 合规分的平均值 |

### 未检测维度如何处理

- 支持度最容易被跳过：没开大模型、或 15 条引文都没取到摘要时，全部为 `not_checked`。
  此时该维度 **不参与总分**，`confidence`（已检测权重 / 100）会下降，页面上写明「未检测」。
- 真实性全部 `Unknown`（断网 / 数据源全挂）时不冒充 0 分或满分，同样视为未检测。
- 相关性只统计数字编号引用；纯作者-年制论文的覆盖口径另见 `citation_anchor.coverage()`，
  没有编号时不强行算 0。

## 等级与置信度

| 总分 | 等级 |
| --- | --- |
| ≥ 95 | A |
| ≥ 85 | B |
| ≥ 75 | C |
| ≥ 60 | D |
| < 60 | E |

`confidence = 可用维度权重之和 / 100`。例如一篇 15 条引文的论文只做了真实性、相关性、
覆盖、规范性四项（25+20+15+15=75），支持度未检测，则置信度为 **0.75**，总分按 75 分权重归一。

## 最该先修

按严重度排序取前 3 条：

1. `Major`（疑似虚构/错配）——高；
2. 支持度 `contradict`（证据与结论方向相反）——高；
3. 正文编号缺失（引用了不存在的条目号）——高；
4. 支持度 `no_evidence`（证据里找不到支撑句）——中；
5. `Unverified`/`Unknown`（没核完，不等于造假）——中；
6. 未被正文引用的参考文献——低；
7. 格式问题集中在某字段（volume/authors/doi…）——按 `stats.issues` 字段计数——低。

## 真实示例

任务 `ddf4a1d38040`（`hanspub_152575.pdf`，15 条参考文献、18 处正文引注、10 页）：

| 维度 | 分数 | 说明 |
| --- | --- | --- |
| 真实性 | 95.0 | 12 Exact / 3 Minor / 0 Major / 0 Unverified |
| 支持度 | 未检测 | 15 条均缺摘要；权重不计入 |
| 相关性 | 100 | 15/15 条被正文引用 |
| 覆盖 | 100 | 15 个编号，0 缺失 |
| 规范性 | 87.7 | 国标均分 87.7，36 处格式问题（volume 30 / authors 5 / doi 1） |

总分 **95.9 / A**，置信度 0.75；最该先修「36 处格式问题」。

## 22 篇真实语料基线

`scripts/eval_health_real.py` 用产品流水线逐篇跑 `data/real_corpus/*.pdf`
（在线核验 + 本地题录库，支持度关闭），结果写 `data/experiments/health_real.json`：

| 指标 | 数值 |
| --- | --- |
| 论文数 | 22 |
| 平均分 | **76.2** |
| 中位数 | 79.2 |
| 范围 | 48.3 – 95.9 |
| 等级分布 | A 1 / B 3 / C 13 / D 1 / E 4 |
| 真实性均值（22 篇） | 57.9 |
| 相关性均值（22 篇） | 79.1 |
| 覆盖均值（17 篇有编号） | 99.8 |
| 规范性均值（22 篇） | 89.3 |

解读：这批真实中文论文里，规范性不是主要短板（89.3），**真实性和相关性才是**——
真实性 57.9 主要来自中文文献在开放索引里查不到（记为 Unverified/Unknown，不等于造假）；
相关性 79.1 表示约五分之一的参考文献没有在正文里找到编号引用。支持度在该语料上没有
摘要可判，因此全部未检测、权重不计（每篇置信度 0.75），这也是均值低于单篇 95.9 的原因之一。

边界：这是同一版本、同一条件（在线核验 + 412 条本地库）下的基线；换数据源、换库、
换解析版本后不可直接比较。脚本可重复运行，但会命中上游缓存；冷缓存时请求更慢，
数据源限流会把个别条目降为 Unknown（脚本不会把它改写成 Major）。

## 边界（不要这么说）

- **不是期刊或学校标准**：权重是我们按产品目标定的，换一组权重分数会变。
- **不是人工评审**：没有人工逐条打分；数据集标签是构造规则决定的。
- **Unverified / Unknown ≠ 造假**：只表示这次没核完，报告里单独计数，不计入 Major。
- **支持度只在该条有可判定摘要时计分**：全部未判定时不要写「支持度 0 分」。
- **不能跨版本比较**：判定提示词、审计版本、数据源健康状态变化后，分数不可直接对比；
  需要对比时用同一版本、同一批数据重跑。

## 复现

```bash
# 跑一篇真实 PDF（本地演示服务）
curl -s -X POST http://127.0.0.1:8013/api/analyze \
  -F paper=@data/real_corpus/hanspub_152575.pdf \
  -F support_max=0
# 报告 JSON 里读 health
python -c "import json;print(json.load(open('data/jobs/<job_id>/report.json'))['health'])"
```
