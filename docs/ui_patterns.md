# 长列表与检查明细

长列表和报告页的“检查明细”在 1.7.3 统一成两种交互：**列表分页**和**右侧抽屉**。
目标不是把内容藏起来，而是让当前要做的事留在视口里，细节按需展开。

## 列表分页

共享组件：`web/static/js/pager.js`（`window.CGList`）。

规则：

- 超过一页（默认 20 条）才显示页码；不超过时只显示「第 1–N 条 / 共 N 条」。
- 控件包含：上一页 / 下一页、页码（含省略号）、每页 10 / 20 / 50、当前范围与总数。
- 页码写入 URL（`?page=2`、`?size=50`），刷新、复制链接、前进后退都保持位置；改筛选或搜索回到第 1 页。
- 切换页码只改 `hidden`，不销毁行，所以勾选、展开状态不会丢；批量操作仍针对当前筛选后的全部数据。
- 键盘可达：页码是 `<button>`，当前页有 `aria-current="page"`，上一页/下一页有 `aria-label`。

已接入的页面：

| 页面 | 挂载点 | 默认每页 | 备注 |
| --- | --- | --- | --- |
| 报告历史 `/history` | `#history-pager` | 20 | 按文件名合并后分页；`?all=1` 查看每次分析 |
| 题录库 `/library` | `#library-pager` | 20 | 搜索后自动回第 1 页 |
| 批量聚合 `/aggregate` | `#ag-pager` | 20 | 逐篇表分页，总览与图表不受影响 |
| 批量判定 `/batch` | `#bt-pager` | 20 | 结果表分页，CSV 仍导出全部行 |
| 报告逐条结果 | 已有 7 条/页 | — | 保留原分页，不再叠加第二套控件 |

评测表（≤11 行）、发现结果（上游已分页）暂不接入；数据量变大后再改为服务端分页。

## 报告「检查明细」抽屉

入口：报告总览右上「检查明细」按钮，或点「对比历史报告」后自动打开到「复检」标签。

- 抽屉从右侧滑入，覆盖 680px，不推挤报告正文，也不会改变页面高度；总览始终停留在结论、健康分和待修项。
- 六个标签：来源健康、图表抽检、支持度、正文引注、图表、复检。没有数据的标签自动隐藏；全部为空时显示「本次没有可展开的检查明细」。
- 每个标签独立滚动；关闭方式：右上 ×、遮罩、Esc。关闭后焦点回到触发按钮。
- 抽屉打开时页面背景滚动锁定；图表在切换标签时调用 `CGCharts.resize()`，修复隐藏容器宽度为 0 的问题。
- DOM 直接复用原面板（不重新请求），所以数据和报告 JSON 完全一致。

截图与复现：

```powershell

python scripts/capture_ux_1_7_3.py
```

## 边界

- 分页是客户端分页：当前报告/题录规模（几百条以内）足够；上万条时应改为服务端分页。
- 抽屉没有做完整的焦点陷阱（Tab 仍可能走到背景），当前只保证 Esc 关闭和关闭后焦点归还；这是下一步可改进项。
- 打印/导出仍使用完整报告 JSON 与导出接口，不受页面分页影响。
