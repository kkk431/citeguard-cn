# 真实论文数据上的解析与核验实测

> 目的：验证「引证卫士」不只在自造样例上能跑，而是在**真实发表的中文论文**上也能用；并量化核验器对真实文献的误报率。
> 数据只存放在本地 `data/real_corpus/`（已 git-ignore），不随仓库分发。

## 1. 语料

| 来源 | 数量 | 内容 |
|---|---|---|
| 汉斯出版社 OA 期刊（hanspub.org） | 20 篇 | 文章页的参考文献原文（409 条）+ 对应 PDF 全文 |
| OpenAlex 开放获取论文 | 2 篇 | PDF 全文（两栏排版、APA 风格英文参考文献，无发布版列表） |

- 22 篇 PDF 里有 1 篇文字层是 CID/自定义字体乱码（239 个 `(cid:…)` 占位符），解析时被护栏识别并走 OCR 兜底，成功解析出 22 条参考文献；**不装 OCR 时会明确提示「文字层损坏」而不是输出乱码**。
- 语料覆盖中英文、两栏/单栏、GB/T 与 APA 两种著录风格。

抓取脚本：`scripts/fetch_hanspub_corpus.py`、`scripts/fetch_real_corpus.py`。
（注：软件学报等期刊站有反爬校验，未纳入；汉斯与 OpenAlex 均可直接获取。）

## 2. 参考文献解析（`scripts/eval_parse_real.py`）

指标：字段覆盖率（题名/作者/年份/类型码/来源/DOI/页码）+「可疑条目」比例
（题名缺失或超长、题名混入链接或序号、作者缺失、年份缺失、类型缺失、来源缺失）。

**网页型引文（`EB`）按 GB/T 7714-2025 允许以题名开头、出版年可缺，不计入可疑**；这类条目的作者识别情况单独统计——当前 28 条网页型引文全部识别出机构作者。

| 输入路径（语料） | 条目数（发布版 / PDF） | 干净条目比例（发布版文字） | 干净条目比例（PDF 抽取） |
|---|---|---|---|
| 初始版本（10 篇） | 224 / 345 | 0.387 | 0.310 |
| 迭代后（10 篇，2026-10-22） | 224 / 345 | 0.996 | 0.992 |
| 扩语料后（22 篇，2026-10-23） | **409 / 529** | **1.000** | **0.998**（逐条 527/529 = 99.6%） |

> 口径：干净率是**逐篇平均**，逐条口径见上表括号；`pdf_heading_found` 为 22/22。

迭代中修掉的问题（均为真实语料暴露）：

1. PDF 页眉/页脚（「期刊名 + 页码」「DOI + 页码」）落在参考文献表中间，把一条文献切成三条 → `strip_repeated_lines()` 按「逐字重复」与「仅数字变化的短行」两类模板剔除；
2. 两栏排版导致左右栏文字逐行交错 → 按页面中线裁剪后先左栏后右栏抽取；
3. 社会学期刊常用的 APA 写法 `作者(年份). 题名. 刊名, 卷(期), 页码.` 完全解析失败 → 新增 APA 分支（切分 + 字段抽取）；
4. 作者姓名缩写里的句点被当成条目边界（`…, J. D. (1978).`）→ 条目起点回退到上一处「后面不是年份」的句点；
5. 页码单独成行（`1177.`）被当成新条目、换行后的年份（`2025. https://…`）被当成编号 2025 → 增加条目过滤；
6. **英文网页型引文被拆散**（扩语料后新暴露，单篇 22 条）：`[15] Stanford University. Bio-X: About Bio-X. http://…` 旧解析把链接塞进题名、把机构名同时当作者与来源；`Sakr, M.F. and Goldstein, S.C. …` 这种「姓, 缩写」并列表也被拆开。修法：① 无类型码但有 URL 且无年份/卷期的条目判为 `EB`；② 机构作者整体保留（含 `Harvard John A. Paulson School of Engineering and Applied Sciences` 这种含缩写与 `and` 的长机构名，`Department of …` 子单位并入作者）；③ 链接与 DOI 从题名剥离；④ `拉尔夫·泰勒` 这类带间隔号的译名按一个作者处理。该论文的解析干净率 51.3% → 100%；
7. **裸链接行 / 页脚数字混进参考文献**：PDF 页脚会把页码与链接粘成 `550. https://…`、`112027. https://doi.0rg/…` 一行 → 作为解析噪声过滤，不再进入核验（旧版会让它变成一条空题名条目，且可能被误判为「疑似虚构」）。

剩余已知不足（529 条 PDF 抽取结果中 3 处提示）：2 处是**真实长题名**（英文报告/长标题，非解析错误），1 处是英文 APA 题名内含 `(2017).` 年份样式时作者行归到上一条。

复现：

```bash
PYTHONPATH=src python scripts/eval_parse_real.py
```

### 2.1 扫描件 OCR 兜底（2026-10-23 实测）

真实论文里还有一类输入是**纯图片 PDF**（扫描件）。把 7 页真实论文 PDF 渲染成无文字层图片 PDF，再走 OCR 兜底 + 解析：

| 指标 | 结果 |
|---|---|
| OCR 文本量 | 10054 字符（7 页，150 dpi，CPU 约 132 s） |
| 解析出的参考文献 | **23 / 24 条**（第 1 条编号在 OCR 中丢失，被并入正文） |
| 字段覆盖（23 条中） | 题名 23 · 年份 23 · 作者 21 · 来源 19 · DOI 0 |

> DOI 在 150 dpi 扫描件上基本识别失败（字符太细），这是 OCR 的已知边界：报告会显示缺 DOI 提示，但不会把缺失当成原文错误。

修掉的两个真实 bug（均由这次实测暴露）：

1. `strip_repeated_lines` 把 OCR 单独成行的 `[n]` 当成“页码模板”删除（`[#]` 模板重复 ≥3 次）→ 参考文献编号全部丢失、只解析出 2 条；现在裸编号行不再按页眉页脚处理。
2. OCR 把 `[n]` 识别成独立一行、条目在下一行 → 新增 `_merge_reference_numbers()` 在参考文献区把编号并回条目。

复现（需先装 `requirements-ocr.txt`）：

```bash
PYTHONPATH=src python scripts/make_scanned_pdf.py --input data/real_corpus/xxx.pdf --output out/scanned.pdf
PYTHONPATH=src python scripts/eval_ocr_scanned.py --input data/real_corpus/xxx.pdf --expected-refs 24
```

## 3. 核验误报（`scripts/eval_verify_real.py`）

语料是**已发表**论文的 409 条真实参考文献，因此出现「疑似虚构（Major）」基本可视为误报。
其中 125 条带 DOI：124 条 Crossref 可解析，1 条由中国 DOI 平台落地页解析。

| 版本（语料） | Exact | Minor | Unverified（未找到） | Major（疑似虚构/错配） |
|---|---|---|---|---|
| 初版·检索不到即判虚构（10 篇 224 条） | 74 | 49 | —（不存在该状态） | **101（45.1%）** |
| 引入 `Unverified` + DOI handle 全局检查（224 条） | 76 | 47 | 101（45.1%） | **0（0%）** |
| 作者按姓氏比对 + APA 作者合并 + 中国 DOI 落地页（224 条） | 74 | 50 | 100（44.6%） | **0（0%）** |
| **扩语料后（20 篇 409 条）** | **125（30.6%）** | **87（21.3%）** | **197（48.2%）** | **0（0%）** |

三处根因与修法：

1. **「题名搜不到」被当成「造假」**：中文期刊大量未被 OpenAlex/Crossref 收录，题名检索会返回相似度极低的无关记录，旧规则直接判 `Major`。
   改为：题名相似度 < 0.78 判 `Unverified`（未找到匹配记录），UI 明确写「可能未被数据库收录，也可能引文有误，请人工核对」，并给出百度学术 / Google Scholar / Crossref 的人工核查链接。
2. **Crossref 404 被当成「DOI 不存在」**：DOI 由多家注册机构签发（CNKI、DataCite、JaLC…），Crossref 查不到不代表 DOI 不存在。
   改为：Crossref 404 后再查 `doi.org/api/handles`；若 DOI 在任一机构存在，再尝试 DataCite 元数据与 DOI 落地页（如中国 DOI 平台的「多重解析地址选择页面」）。能解析出题名/作者就按 `doi:landing` 比对并标注「卷期页可能缺」，解析不出才判 `Unverified`。
3. **作者格式差异被当成作者错误**：中文 GB/T 写法是 `Yu, H.`，Crossref/OpenAlex 返回 `Hui Yu`，全名比对把大量正确引文判成 `Minor`。
   改为：①解析器先合并 APA 的 `Surname, I. N.` 片段（此前一整串作者会被拆成 8 个「作者」）；②比对时只比姓氏（`Yu` vs `Hui Yu`），并单独检查作者顺序；③仍然保留「作者列表疑似残缺时不比作者」的兜底。

扩语料后 87 条 Minor 的字段分布：年份 36 处、页码 33 处、作者 11 处、作者顺序 7 处、来源 10 处、题名（含部分匹配）7 处、卷 2 处。报告会逐条列出字段差异与可核查链接。

历史净效果（10 篇 224 条子集上的一次逐条 diff，保留备查）：

- **Unverified → Exact（1 条）**：`10.15886/j.cnki.hnus.202410.0119`，中国 DOI 平台落地页给出题名/作者/来源，题名与作者一致。
- **Exact → Minor（2 条）**：其中 1 条是真实错误（`Yi, H.X. and Yang, C.C.` 的书实际作者顺序为 Yang & Yi，原报告漏检），另 1 条是书名相同但检索到的记录是书评（作者完全不同）。
- **Minor 新增 authors 字段（6 条）**：均按「题名/年份/卷期也同时不一致」核对过，属于检索到的记录不是同一篇文献（书评、同题综述），不是新增误报；对这类「题名一致但作者完全对不上」的条目，报告会附一句「匹配记录可能是书评/同名不同作品，请核对作者」。

> 诚实说明：真实已发表文献的 Major 始终为 0，没有把任何真实文献说成造假；代价是 **48.2%** 的中文文献只能给「未找到匹配」——这是中文文献在国际开放元数据中覆盖不足的客观限制（见 §5）。

### 3.1 网页型引文的链接核验（2026-10-23 新增）

中文社科论文常引用英文机构网页（`[15] Stanford University. Bio-X: About Bio-X. http://…`）。这类引文不在学术索引里，题名检索必然「未找到」，但**链接本身就是证据**。新增一层核验：

- 对 `[EB/OL]` 且带 URL 的条目，先检查链接可达性并读取页面 `<title>`：可达且标题与引文题名一致 → 判 `Exact`（结论里写明 HTTP 状态与相似度）；标题不一致 → 提示人工核对；链接失效/需要登录 → **只提示「可能链接腐化」，绝不判「疑似虚构」**。
- **SSRF 防护**：只允许 http/https、只允许 80/443 端口，解析出的 IP 必须是公网地址（拒绝 localhost / 内网 / 回环 / 保留地址），响应体截断 300 KB、8 s 超时、按 URL 缓存；`CITEGUARD_URL_CHECK=0` 可完全关闭（离线部署用）。
- 真实语料实测（23 条网页引文）：**13 条链接可达且页面标题一致（Exact）**，3 条页面标题不一致，7 条被站点 403/访问受限（如实标为「无法自动核验」）。
- 净效果：409 条真实引文的确定结论从 201 条升到 **212 条（51.8%）**，Major 仍为 **0**。

> 对自建 CiteBench-CN 的影响：`Unverified` 在 3 分类评测中映射为 `Major`（非「已确认造假」，仅表示未匹配到记录），
> 因此 benchmark 指标不变：macro-F1 **0.9684**、accuracy **0.968**，混淆矩阵 `[[100,0,0],[8,67,0],[0,0,75]]`。

## 4. 本地题录库：把中文覆盖率从 49% 拉到 100%（`scripts/eval_library_real.py`）

中文文献在国际开放数据里的覆盖率是硬约束（§3：中文标题引文约 48% 查不到）。用户手上其实有这些记录（知网 / NoteExpress / EndNote / Zotero 导出的题录），所以新增了「本地题录库」：

- 支持 RIS / EndNote / BibTeX / CSL-JSON / 纯文本参考文献表导入；
- 核验时先比对本地库，命中则做字段级比对（年份、作者、来源、卷期、页、DOI），未命中再回退在线源；
- 数据只保存在本机 `data/library/library.json`，不上传。

实测设置（避免自证）：**库**由 20 篇真实论文「发布版参考文献表」构建（408 条，模拟用户导出），**输入**是同一批论文的 **PDF 抽取**结果（409 条，已过滤裸链接等解析噪声），因此 PDF 解析误差会以字段偏差形式暴露。

| 指标 | 无本地库 | 导入本地库 |
|---|---|---|
| 能给出结论（Exact + Minor） | 212 / 409（51.8%） | **409 / 409（100%）** |
| 未找到匹配 | 197（48.2%） | 0 |
| 其中检出字段偏差（Minor） | 87 | **4**（来自库内比对，可定位到具体字段） |

结论：本地题录库是当前合规条件下解决中文文献核验的可行路径；代价是用户需要导入自己的题录导出（一次性操作）。库里没有的条目自动回退在线核验，不会更差。

> **口径修订（2026-10-23）**：早期版本报过「检出 34 条字段偏差」，复核发现其中 32 条是 PDF 提取把 APA 作者列表拆成片段（`D.`、`et al.`）后与题录库比对的**假偏差**。
> 现在的处理：①解析器把 `Surname, I.` 重新合并、过滤独立的 `et al.`；②作者字段残缺时**不做作者比对**，只在格式层给 warning（「作者字段疑似不完整」）；③年份/卷/期/页/来源照常比对。
> 20 篇语料下真实检出 4 条；逐条核对原始条目，均为 PDF 抽取排版差异（重复行导致年份不一致 1 条、栏间文字粘连进题名 2 条、页码/断词 1 条），而不是论文的引用错误。
> 这条修订本身是产品可信度的一部分：宁可少报，也不把解析噪声当成论文的错误。

## 5. 中文覆盖率还能不能再挖（2026-10-23 补测）

在定「中文文献只能靠本地题录库」这个结论前，先确认两件更便宜的事：一是**检索没做好**，还是**数据源里根本没有**；二是**DOI 注册机构**能不能补一部分元数据。

### 5.1 检索召回：不是瓶颈（`scripts/experiment_search_recall.py`）

从 CiteBench-CN 的中文作品池（OpenAlex CC0）取 25 篇**确实被 OpenAlex 收录**的中文论文，用当前检索策略回搜：

| 策略 | 命中率 |
|---|---|
| OpenAlex 标题检索（当前实现） | **0.92** |
| OpenAlex 标题 + 年份 | 0.92 |
| OpenAlex `search` 参数 | 0.84 |
| Crossref `query.bibliographic` | 0.80 |

结论：能被收录的中文文献，当前检索基本找得到；`Unverified` 的 197 条主要是**数据源未收录**，不是查询写法问题。继续调检索参数的收益有限。

### 5.2 中国 DOI 注册平台：能补，但覆盖面小

CNKI/万方签发的 DOI 不在 Crossref。实测 `10.15886/j.cnki.hnus.202410.0119`：

- `doi.org/api/handles/<doi>` 返回 200（DOI 真实存在）；
- `https://doi.org/<doi>` 落地页（中国 DOI 的「多重解析地址选择页面」）含 `题名 / 作者 / 来源 / 出版机构 / DOI码`，可稳定解析；
- 已接入为 `doi:landing`：题名、作者一致就判 `Exact`，并标注「外部注册机构元数据有限，卷期页可能缺」。

但**409 条真实参考文献里只有 1 条带这类 DOI**（125 条带 DOI，其中 124 条 Crossref 能解析；中文论文普遍不在参考文献里写 DOI），所以它只能算补丁，解决不了覆盖率问题。

### 5.3 结论

按「投入产出」排序，中文文献核验的正确路径是：**本地题录库（用户自己的知网/EndNote 导出）> 中国 DOI 落地页 > 在线检索**。前两者已实现；不建议去抓取知网/万方（授权与合规风险，且需要登录态）。

## 6. 结论与局限

- 解析层在真实论文上已可用（发布版 100%、PDF 路径逐条 99.6% 干净率），前提是 PDF 有文字层；扫描件与文字层损坏的 PDF 走 OCR 兜底并给出明确提示。
- 核验层对真实文献的**Major 为 0**；代价是 48.2% 的中文文献只能给「未找到匹配」——产品选择「宁可说未核实，也不误指控」。导入用户自己的题录库后这一比例降到 0。
- 未覆盖：知网/万方等需授权的中文全文库；本工具不抓取、不转存这些数据。
