# 真实论文数据上的解析与核验实测

> 目的：验证「引证卫士」不只在自造样例上能跑，而是在**真实发表的中文论文**上也能用；并量化核验器对真实文献的误报率。
> 数据只存放在本地 `data/real_corpus/`（已 git-ignore），不随仓库分发。

## 1. 语料

| 来源 | 数量 | 内容 |
|---|---|---|
| 汉斯出版社 OA 期刊（hanspub.org） | 10 篇 | 文章页的参考文献原文（224 条）+ 对应 PDF 全文 |
| OpenAlex 开放获取论文 | 2 篇 | PDF 全文（含两栏排版） |

抓取脚本：`scripts/fetch_hanspub_corpus.py`、`scripts/fetch_real_corpus.py`。
（注：软件学报等期刊站有反爬校验，未纳入；汉斯与 OpenAlex 均可直接获取。）

## 2. 参考文献解析（`scripts/eval_parse_real.py`）

指标：字段覆盖率（题名/作者/年份/类型码/来源/DOI/页码）+「可疑条目」比例
（题名缺失或超长、作者缺失、年份缺失、类型缺失、来源缺失、题名里混入序号）。

| 输入路径 | 解析条目数 | 干净条目比例（发布版文字） | 干净条目比例（PDF 抽取） |
|---|---|---|---|
| 初始版本 | — | 0.387 | 0.310 |
| 迭代后 | 224 → 205 | **0.996** | **0.992** |

迭代中修掉的问题（均为真实语料暴露）：

1. PDF 页眉/页脚（「期刊名 + 页码」「DOI + 页码」）落在参考文献表中间，把一条文献切成三条 → `strip_repeated_lines()` 按「逐字重复」与「仅数字变化的短行」两类模板剔除；
2. 两栏排版导致左右栏文字逐行交错 → 按页面中线裁剪后先左栏后右栏抽取；
3. 社会学期刊常用的 APA 写法 `作者(年份). 题名. 刊名, 卷(期), 页码.` 完全解析失败 → 新增 APA 分支（切分 + 字段抽取）；
4. 作者姓名缩写里的句点被当成条目边界（`…, J. D. (1978).`）→ 条目起点回退到上一处「后面不是年份」的句点；
5. 页码单独成行（`1177.`）被当成新条目、换行后的年份（`2025. https://…`）被当成编号 2025 → 增加条目过滤。

复现：

```bash
PYTHONPATH=src python scripts/eval_parse_real.py
```

## 3. 核验误报（`scripts/eval_verify_real.py`）

语料是**已发表**论文的 224 条真实参考文献，因此出现「疑似虚构（Major）」基本可视为误报。

| 版本 | Exact | Minor | Unverified（未找到） | Major（疑似虚构/错配） |
|---|---|---|---|---|
| 改进前 | 74 | 49 | —（不存在该状态） | **101（45.1%）** |
| 改进后 | 74 | 49 | 101（45.1%） | **0（0%）** |

两处根因与修法：

1. **「题名搜不到」被当成「造假」**：中文期刊大量未被 OpenAlex/Crossref 收录，题名检索会返回相似度极低的无关记录，旧规则直接判 `Major`。
   改为：题名相似度 < 0.78 判 `Unverified`（未找到匹配记录），UI 明确写「可能未被数据库收录，也可能引文有误，请人工核对」，并给出百度学术 / Google Scholar / Crossref 的人工核查链接。
2. **Crossref 404 被当成「DOI 不存在」**：DOI 由多家注册机构签发（CNKI、DataCite、JaLC…），Crossref 查不到不代表 DOI 不存在。
   改为：Crossref 404 后再查 `doi.org/api/handles`，若 DOI 在任一机构存在则判 `Unverified`（无元数据可比对），只有全局 DOI 系统也无记录才判 `Major`。

> 对自建 CiteBench-CN 的影响：`Unverified` 在 3 分类评测中映射为 `Major`（非「已确认造假」，仅表示未匹配到记录），
> 因此 benchmark 指标不变：macro-F1 **0.9684**、accuracy **0.968**，混淆矩阵 `[[100,0,0],[8,67,0],[0,0,75]]`。

## 4. 本地题录库：把中文覆盖率从 2% 拉到 100%（`scripts/eval_library_real.py`）

中文文献在国际开放数据里的覆盖率是硬约束（第 3 节：中文标题引文 100 条里 98 条查不到）。用户手上其实有这些记录（知网 / NoteExpress / EndNote / Zotero 导出的题录），所以新增了「本地题录库」：

- 支持 RIS / EndNote / BibTeX / CSL-JSON / 纯文本参考文献表导入；
- 核验时先比对本地库，命中则做字段级比对（年份、作者、来源、卷期、页、DOI），未命中再回退在线源；
- 数据只保存在本机 `data/library/library.json`，不上传。

实测设置（避免自证）：**库**由 10 篇真实论文「发布版参考文献表」构建（223 条，模拟用户导出），**输入**是同一批论文的 **PDF 抽取**结果（224 条），因此 PDF 解析误差会以字段偏差形式暴露。

| 指标 | 无本地库 | 导入本地库 |
|---|---|---|
| 能给出结论（Exact + Minor） | 49 / 224（22%） | **224 / 224（100%）** |
| 未找到匹配 | 101（45%） | 0 |
| 其中检出字段偏差（Minor） | 49 | 34（来自库内比对，可定位到具体字段） |

结论：本地题录库是当前合规条件下解决中文文献核验的可行路径；代价是用户需要导入自己的题录导出（一次性操作）。库里没有的条目自动回退在线核验，不会更差。

## 5. 结论与局限

- 解析层在真实论文上已可用（PDF 路径 0.992 干净率），前提是 PDF 有文字层；扫描件仍需 OCR。
- 核验层对真实文献的**误报率从 45% 降到 0**，代价是 45% 的中文文献只能给「未找到匹配」——这是中文文献在国际开放元数据中覆盖不足的客观限制，产品选择「宁可说未核实，也不误指控」。
- 未覆盖：知网/万方等需授权的中文全文库；本工具不抓取、不转存这些数据。
