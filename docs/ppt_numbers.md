# 答辩/PPT 数据一页纸

> 用途：答辩 PPT 里可直接引用的**已核实数字**。每条都给了口径、复现命令和证据文件，评委追问时能当场跑。
> 原则：只写真实测得的数；数据集构造的局限性必须一起说（见文末「不能这么说」）。

## 一句话定位

**引证卫士 CiteGuard-CN**：中文论文的引文体检工作台——逐条核验参考文献是否真实存在、是否真的支持正文那句话、是否符合 GB/T 7714-2025 著录格式；本地部署、开源、自带两个中文评测集。

## 演示动线（3 分钟）

1. 首页拖入示例论文 → 报告：四类结论 + 每题证据链接；
2. 批量上传 2 篇 → 汇总面板（篇数/条数/各状态/格式均分）+ 导出 CSV；
3. 报告页点「支持度矛盾」筛选 → 展示「元数据一致但正文与原文矛盾」条目；
4. 题录库页展示搜索/删除/一键补摘要（只补缺摘要，标题相似度 ≥ 0.92 才接受）；回报告看「本地题录库」标签；
5. 图表核验页传一张图 + 结论 → 现场得到 supported/contradicted/insufficient 与理由（需 GPU 视觉服务）；
5b. 文献对比页传 2–4 篇同主题论文 → 六维矩阵 + 导出 Markdown/CSV（约 2 秒/篇）；
5c. 文献发现页输入「人工智能 教育」→ 自动中英双语扩展，20 条带摘要的候选卡片（上游命中 114 万条，冷启动约 6–10 秒）→ 勾选入库；
6. 评测页 `/benchmark`：核验 / 支持度 / 开源判官 / 图表 / 对比 / 发现 / OCR 七块数字一屏看完，附运行状态自检（判官、审计、并发、访问控制、OCR、视觉模型、题录库、磁盘）。

## 不能这么说（会被当场问穿）

1. **不要说「支持度准确率 95%，适用于任意论文」**：ClaimSupport-CN 是程序化构造集（标签由构造决定，无人工双标、无 κ）；应说「在自建中文支持度评测集上 macro-F1 0.9597」。
2. **不要说「中文文献都能在线核验」**：真实语料里英文 93.5% 可自动确认，免费源中文只有 12.4%（210 条中文引文仅 26 条命中）——中文期刊大多不在 OpenAlex/Crossref 的开放索引里，这是覆盖缺口不是造假；配置万方 API 后中文强匹配 65.2%、整体 79.0%（模糊命中另计）；产品会对未命中的中文条目提示并给知网/百度学术检索入口，本地题录库可把可判定率拉到 100%，但需要用户导入自己的题录。
3. **不要说「覆盖知网/万方全文」**：产品不抓取、不转存授权全文；只消费用户自己导出的题录与公开元数据。
4. **不要说「用户实测/用户满意度」**：目前只有内部实验（E4/E5/E7 是内部实验），没有真人用户研究；用户测试包已备好在 `docs/user_test_kit.md`（3–5 人可跑）。
5. **不要说「格式检查覆盖 GB/T 全部规则」**：E4 是构造漂移回归（29/30），规则引擎仍是有边界的；页码连接号只是 warning，卷/期为小数字时无法判断互换。
6. **「0/409 误判」的前提是这 409 条来自已发表论文**；换成论文写作中的草稿/伪造引文，系统会通过 Major 正常报出来（CiteBench 里 75 条构造虚构全部检出）。
7. **不要说「抓假率 98.5%」**：98.5%（197/200）是「对 40 条带 DOI 真实引文注入 5 类错误」的检出率；无 DOI/URL 锚点的拼接伪造 13 条全部是 Unverified（按设计不指控），不能混进来。完整口径见 `docs/experiments.md` §8。
8. **不要说「图表核验 94%，可以替代人工看图」**：50 条主口径里真实图只有 5 张、结论是人工写的，样本很小（扩容后 13 张/26 条也只 0.885）；0.94 是「粘贴正文/图注后」的口径，仅图是 0.90。它只判「这张图/这段正文和这句话是否一致」，不做版面分析、不核对图表数据来源，`insufficient` 仍需人工看。
9. **不要说「多篇对比能自动写综述 / 字段准确率 90%」**：字段是模型从摘要与正文前部抽的，没有字段级标注集；只有 4 篇真实论文的工程实测（4/4 成功、8.0 秒、每篇 5–6/6 字段）。它把论文并排成矩阵，不做跨文献综合，研究空白仍要人来写。
10. **不要说「文献发现能替代知网检索 / 排序很准」**：它只查 OpenAlex 开放元数据，中文召回取决于 OpenAlex 覆盖；查询扩展依赖判定模型，不可用时会退化为原查询；排序是写死的启发式规则，没有任何 relevance 标注集，不报告 NDCG/准确率；入库只存题录，不等于已核验。
11. **不要说「我们打赢了 RefChecker」**：那是同数据（SciFact 300 条）、同底层模型（DeepSeek-Chat）、按其官方两段式流水线的对照；RefChecker 是通用「回复—证据」幻觉检查器，不是为引文支持度设计，其 README 主要面向 GPT-4 级模型。只能说「在本任务上，本工作台的协议更合适（macro-F1 0.822 vs 0.765）」。

## 创新性怎么写（三条，别写成「用了大模型」）

评分表「创新性（20 分）」看的是「有没有真东西」，不是「有没有新算法」。答辩口径建议压成三条：

1. **判定链可解释，不靠模型猜。** 每条引文先走检索锚定（DOI / arXiv ID / 题名）和匹配护栏，只有可靠匹配才让模型判支持度；判定再拆成「先判支持/矛盾/无证据，再审计证据是否覆盖引用句全部要素」。结论页能点回来源、字段差异和证据句。
2. **判官可替换，且有同口径实测。** 同一套 100 条评测上，托管 API、开源 14B bf16、14B 4-bit、8B、3B VL 全部跑过：14B 0.9744 略超托管 0.9597，4-bit 0.9754 只要 11.7 GB 显存；不拿单点最好数字代表整体。
3. **评测即产品，错误也开放。** 自建 250 条核验集 + 100 条支持度集 + 22 篇真实论文 409 条引文，外加 SciFact / ChartCheck 外部零样本；错误 JSON、复现脚本、失败分析一起进仓库。页面上的每个数字都能在评测页点回复现入口。

一句话总结：**创新点不是「我们用了大模型」，而是「把生成式判断拆成可验证的环节，并让每个结论都带证据、可复现、可替换」。**
