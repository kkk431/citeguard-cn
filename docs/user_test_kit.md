# 真实用户测试包（可直接照做）

> 这是**给真人用的测试脚本**，不是已经完成的用户研究。当前仓库里所有数字都只来自内部实验（`docs/experiments.md` 的 E4/E5/E7 明确标注为内部自测），**不能**写成「用户实测 / 用户满意度」。
> 目的：用 3–5 位真实用户验证两件事——(1) 产品是否看得懂、用得上；(2) 核验结论是否被信任、误报能否被用户识别。

## 0. 被测对象与准备

- 演示地址（按实际环境选一个）：
  - 本机：`http://127.0.0.1:8010`
  - 远程（SSH 隧道）：`ssh -L 18000:127.0.0.1:8000 <user>@<host>`，然后 `http://127.0.0.1:18000`
- 环境要求：能配 `DEEPSEEK_API_KEY` 则支持度判定可用；不配也能测「真实性 + 格式 + 导出」，只是支持度显示「未检测」。
- 受试者画像：正在写论文的研究生 / 青年教师（有参考文献整理经历即可），不需要懂编程。
- 每组 30–40 分钟；需要一名主试（读任务、记录）和一名观察员（可选）。

## 1. 测试前（5 分钟）

1. 说明：这是产品可用性测试，不是考试；没有标准答案；全程可以吐槽。
2. 说明数据：上传文件仅用于本次分析、分析后删除；题录库只存本机；不会上传到第三方。
3. 签到表（匿名编号即可，不要收集姓名以外的个人信息）：

| 编号 | 身份（硕/博/教师） | 学科 | 是否有知网/EndNote/Zotero 使用经验 | 同意录音/录屏 |
|---|---|---|---|---|

## 2. 任务脚本（主试照读，不要替用户操作）

### T1 · 上传一篇自己的论文（8 分钟）

> 「请把你论文的 PDF（或 Word/TXT）上传，点开始体检。等报告出来后，告诉我：这篇论文里哪些参考文献需要你处理？你怎么看出来的？」

观察点：能否找到上传入口；是否理解四类结论；是否注意到「未找到匹配 ≠ 造假」；会不会点开证据链接。
记录：完成（是/否）、耗时、卡住的位置、原话（出声思考）。

### T2 · 导入自己的题录库（8 分钟）

> 「中文文献在公开库里覆盖很少。请到『题录库』页，导入你从知网/EndNote/Zotero 导出的题录文件（RIS/BibTeX/EndNote/CSL-JSON 都行），再回去重新体检一次同一篇论文。对比两次结果有什么变化？」

若用户没有题录文件：主试提供 `data/real_corpus` 里的示例 RIS（不要提供含隐私的文件）。
观察点：能否在页面上看懂「数据只存本机」；导入后是否理解「本地题录库」标签与命中数；是否理解「带摘要」的意义。
记录：完成、耗时、两次结果差异的复述是否准确。

### T3 · 判断两条「未找到匹配」（6 分钟）

主试从报告中挑 2 条 `Unverified`，提问：

> 「这两条显示未找到匹配。你觉得它们可能是造假吗？你会怎么核实？」

观察点：是否会使用报告里的百度学术 / Google Scholar / Crossref / DOI 原文页链接；是否把「未找到」误当成「造假」。
记录：用户结论与真实情况（主试可提前用 CNKI/百度学术核对）。

### T4 · 导出与交接（4 分钟）

> 「如果要把这份报告发给导师/同学，你会导出哪个格式？为什么？」

观察点：CSV / HTML / Markdown / JSON 四个按钮是否可发现；批量上传 + 汇总面板是否被理解（可加测：一次选 2 个文件）。
记录：选择的格式与理由；是否发现「打印 / 存 PDF」。

### T5 · 收尾访谈（5 分钟）

1. 三句话内，这个工具是做什么的？你会推荐给同学吗？为什么？
2. 哪一条结论你最不信任？为什么？
3. 如果只能保留一个功能，你留哪个？
4. 你希望它下一步做什么？（记录原话，不要引导）

## 3. 可量化指标（汇总到结果表）

| 指标 | 定义 | 目标（参考） |
|---|---|---|
| T1 完成率 | 独立完成上传并说出需处理条目 | ≥ 4/5 |
| T1 平均耗时 | 上传→看懂结论 | ≤ 5 min |
| 四类结论理解率 | 能正确区分「元数据偏差 / 疑似虚构 / 未找到匹配 / 无法核验」 | ≥ 4/5 |
| 误报识别 | 对 2 条 Unverified 不误判为造假，且会去人工核对 | ≥ 4/5 |
| 题录库导入完成率 | 独立完成导入并复述变化 | ≥ 3/5 |
| 导出可发现性 | 30 秒内找到任一导出入口 | ≥ 4/5 |
| 信任度（1–5） | 「我愿意相信这份报告的结论」 | 均值 ≥ 3.5 |
| SUS 总分 | 10 题标准量表，换算 0–100 | ≥ 70 |

## 4. SUS 问卷（中文版，1=非常不同意，5=非常同意）

1. 我愿意经常使用这个工具。
2. 我觉得这个工具没有必要这么复杂。
3. 我觉得这个工具容易使用。
4. 我觉得需要技术人员帮助才能使用这个工具。
5. 我觉得这个工具的各项功能整合得很好。
6. 我觉得这个工具有太多不一致的地方。
7. 我觉得大多数人能很快学会使用这个工具。
8. 我觉得这个工具用起来很麻烦。
9. 使用这个工具时我很有信心。
10. 我需要先学很多东西才能使用这个工具。

计分：奇数题 `得分 = 选项 - 1`；偶数题 `得分 = 5 - 选项`；总和 × 2.5 = SUS 分数（0–100）。

## 6. 执行注意

- 不要引导用户说出我们想要的答案；「你说的『未找到匹配』是什么意思？」这种追问可以，解释功能不行。
- 用户上传自己的论文前，确认其知情同意；测试后请用户自行删除浏览器下载的报告文件，服务端任务目录按保留策略自动清理（默认保留最近 100 个任务 / 7 天，见 `jobs.cleanup`）。
- 任何「用户实测」表述都必须附上受试者人数、任务版本（commit）、日期；否则按内部测试口径写。
