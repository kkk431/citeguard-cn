# 「AI+开源」方向一：规则逐条对照与事实材料

> 用途：答辩/技术报告的事实底稿，不是宣传稿。所有数字都能在仓库里找到对应文件与复现命令；
> 没有测过的能力写「未测」，不写「领先」。

## 1. 方向与硬性要求

参赛方向：**（一）开源赋能的 AI 应用创新**。申报时只按这个方向写，不蹭「开源项目改进」
（我们没有对某个上游项目做持续维护）或「综合创新」。

规则里最容易被判「不合格」的几条，逐条对照：

| 规则要求 | 我们的实际情况 | 证据 |
|---|---|---|
| 应用类作品应突出开源资源对核心功能的关键作用 | 核心判定链路用到的模型、数据、组件全部有明确开源许可；换掉开源模型，支持度/图表核验能力直接失效 | 本文 §2、§3 |
| 不得仅简单调用通用模型接口、拼装现成工具、套模板换界面 | 判定不是模型直出：规则引擎 + 题录检索 + 两段式支持度 + 匹配度护栏 + 本地库比对，且每层都有消融/对照数字 | §4 |
| 团队自主完成，不得把他人成果作为团队成果 | 自研代码约 5.1k 行（`src/`），评测集与文档自建；第三方只作为基础能力，边界见 §3 | `src/`、`tests/`、`data/` |
| 必须提交《开源及第三方资源使用清单》 | 权威清单在 `THIRD_PARTY_NOTICES.md`；本文 §2 给出摘要版 | `THIRD_PARTY_NOTICES.md` |
| 至少一种可复用/可验证的开放成果 | Apache-2.0 代码仓、CC-BY-4.0 两个数据集、证据 JSON、复现脚本、上游 PR | §5 |
| 公开成果不得包含无权再分发内容 | 真实论文 PDF 不进仓、不外发；只保留公开元数据 ID 与统计结果 | `.gitignore`、`data/real_corpus/` 不跟踪 |
| 技术报告等材料匿名（不得出现学校/LOGO/指导教师） | 仓库与技术文档不含学校名、教师名；交付 zip 不含 `.git` 历史 | 已扫描 README/NOTICE/LICENSE |
| AI 生成内容须说明用途与参与环节 | 见 §6 | — |

## 3. 自主实现边界（哪些是我们的，哪些不是）

**自研部分**

- 中文参考文献解析：APA/GB/T 混合、机构作者、网页引文、OCR 噪声修复（`src/citeguard/reference_parser.py`）。
- 引文真实性核验：标题/作者/年份/卷期页比对、DOI 状态机、撤稿标记、链接核验（`metadata_verify.py`）。
- GB/T 7714-2025 规则引擎与参考文献表重排（`gbt7714.py`、`format_gbt.py`）。
- 引用支持度：两段式判定 + 覆盖审计 + 匹配度护栏 + 缓存分键（`support.py`、`pipeline.py`）。
- 图表-结论核验、多篇文献对比、选题发现、审稿视角汇总、正文引注一致性（`figure_check.py`、`compare.py`、`discover.py`、`report.py`）。
- 两套自建中文评测集与全部评测脚本（`data/citebench_cn`、`data/claimsupport_cn`、`scripts/`）。

**第三方基础能力（不主张为自研）**

- 大模型权重与推理：Qwen 系列（Apache-2.0），通过 transformers/OpenAI 兼容服务调用。
- 文献元数据：OpenAlex/Crossref/DataCite/arXiv 的公开接口。
- PDF 文本层抽取、OCR、Web 框架等通用库。
- 默认托管判官：DeepSeek API；产品设计成可替换，且有本地开源模型实测。

**没有做的事（避免过度声明）**

- 没有训练或微调任何大模型；没有自研向量模型/OCR 模型。
- 没有购买算力；没有真实用户大规模测试（只有 12 条人工对照的小样本）。
- 没有把第三方全文/摘要打包再分发。

## 4. 「不是简单调 API」的证据

同一任务、同一数据、可复现的对照（详细出处见 `docs/ppt_numbers.md`）：

| 对照 | 直接调用通用模型 | 本系统 | 差距来源 |
|---|---|---|---|
| 中文引文真实性分类（CiteBench-CN 250 条） | DeepSeek 零样本 macro-F1 **0.5159** | **0.9684** | 检索 + 规则 + 模型分工，不是让模型背分类 |
| 引用支持度（ClaimSupport-CN 100 条） | 单段 judge 0.9005 | 两段式 **0.9328** | 覆盖审计 + 匹配度护栏 |
| 真实文献注入错误（409 条真实引文 × 5 类变异） | — | 检出 **197/200（98.5%）** | 字段级比对而非整句判断 |
| 图表-结论（合成 40 条 + 真实 10 条） | — | 0.90 / 0.90，误报矛盾 0 | 视觉模型 + 判定 prompt + 结构化输出 |
| 开源模型本地化（Qwen3-14B + v7，留出 test 60） | — | **0.9063**（同口径托管 0.9470） | 自托管可复现，差距 4.1 分如实报告 |

补充对照：同一 100 条上，7B 本地模型产品路径 0.7181；14B 换审计 v2 后在 test 60 上 0.8887，加少样本 v7 后 0.9063；
提示词工程（v6/v7）、混合审计 v3、3 票自洽都没有超过单票 v2——这些失败尝试也留在仓库里。

## 5. 开放成果

1. **代码**：<https://github.com/kkk431/citeguard-cn>，Apache-2.0（`LICENSE`、`NOTICE`）。
2. **数据集**：CiteBench-CN（250 条）、ClaimSupport-CN（100 条），CC-BY-4.0，含数据卡与标注说明；
   只含自建标注与公开元数据 ID，不含第三方全文/摘要。
3. **可验证证据**：`data/experiments/*.json`（含原始预测、混淆矩阵、延迟）、`scripts/verify_artifacts.py`
   （本机 106 项 / 远端 115 项一致性检查）、`reproduce.sh` 一键复现。
4. **上游贡献**：向 RefChecker（MIT）提交过 PR #77（BibTeX 裸字段解析，避免数字年份被丢弃）；
   是否合并以 GitHub 页面实时状态为准，不写成「已合并」。
5. **文档**：部署手册、评测规划、真实语料实测、支持度总结、图表核验、文献发现、本对照表。

## 6. AI 工具使用说明（按规则披露）

- 开发与写作过程中使用了 AI 编程助手（DeepSeek Harness / 大模型代码助手）辅助生成、修改代码与文档；
  所有改动由团队负责人逐项审核、运行测试并复核数字。
- 产品运行时默认调用 DeepSeek API 作为判官；也支持完全本地开源模型（Qwen 系列），两者都有实测。
- 评测数据由团队构建与标注；AI 不参与「人工真值」的最终裁定。
- 未使用 AI 生成图片/视频冒充真实实验结果；图表核验的合成图由脚本生成并明确标注为合成控例。

## 7. 已知短板（答辩时主动说，别等评委问）

- 真实语料只有 20 篇中文 OA 论文 / 409 条参考文献，且 48.2% 在无本地库时只能判「未找到」，
  不等于「造假」；接入机构库/CNKI 才能提高可判定率。
- 开放模型 14B 最好配置仍与托管 DeepSeek 差 4.1 分；test 只有 60 条，14B 的 dev/test 有波动（0.8676 → 0.8887/0.9063）。
- 上游社区贡献目前只有 1 个 PR，影响力有限；没有维护独立开源社区。
- 没有真人用户研究；只有 12 条人工核对的小样本一致性。
- 图表核验的真实图只有 5 张/10 条 claim；文献发现依赖 OpenAlex 的覆盖与英文索引。
