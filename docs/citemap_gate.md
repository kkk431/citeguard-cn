# CiteMap 证据门禁：为什么不能把“相关句”直接叫证据

> 目的：把 105 格三人核对中发现的问题落到产品规则上，而不是继续用“机器候选”冒充证据。

## 1. 背景

105 格全量人工核对中，v1 机器证据 31 格：

- 人工多数票判“正确” **8/31（25.8%）**；
- 判“有问题” 23 格，问题类型主要是断言错配（59 次）和立场错（2 次）；
- 无机器证据的 70 格中，69 格判“无证据”正确，说明核对人理解任务，问题在机器抽取。

## 2. 门禁实验

用严格 claim-evidence judge 对 31 条原证据句重新判断，和人工多数票对齐。

### 2.1 宽松门禁（只要求“支持断言的核心部分”）

`data/experiments/citemap_gate_v2.json`：

- 保留 11 条，其中人工判正确 7 条 → **精确率 63.6%**；
- 人工正确 8 条中保留 7 条 → **召回 87.5%**；
- 但保留的 4 条被人工判“有问题”，原因都是**只支持复合断言的一部分**，模型把“部分支持”标成了 support。

### 2.2 全量支持门禁（要求覆盖整条复合断言）

`data/experiments/citemap_gate_v3.json`：

- 31 条证据中，判为“完整支持整条断言”的 **0 条**；
- 人工判“正确”的 8 条，也全部只是“部分支持”。

结论不是“再调一次提示词”，而是：**复合断言 + 单句摘要证据这个数据结构本身就不成立**。一句摘要通常只能支持断言的一个原子部分，不能支持整条复合断言。

## 3. 产品规则（1.7.26）

1. **复合断言不再展示单句“机器证据”**。原 v1 证据只保留在 105 格审计文档里作为历史记录，不作为产品结论。
2. **原子断言单独展示“原子证据”**。每条原子证据只对应一条原子命题，标注“仅摘要 · 未人审”。
3. **论文自述结论单独标“论文自述结论”**。这是论文摘要里的一句结论，不是对人工断言的证据，不能当断言成立依据。
4. 统计分开：人工示例、原子证据、论文自述、机器候选不再混成一个“机器证据”数字。
5. 动态生成地图沿用同一规则：机器层只作为候选，人工层和机器层物理分开。

## 4. 当前能力与边界

- 原子证据：9 条 / 7 篇 / 7 个有核对格；三人多数判正确 **5/7（71.4%）**。
- 105 格人工核对：Fleiss κ 0.6587；复合断言 v1 证据精确率 25.8%；无证据 69/70 正确。
- 原子层仍然是摘要级、未人审、样本小；不能写成“已验证支持整条断言”。

## 5. 复现

```bash
PYTHONPATH=src python scripts/gate_citemap_evidence.py \
  --key dist/citemap_audit_full/_organizer_only_key.csv \
  --merged data/experiments/citemap_audit_105/merged.csv \
  --out data/experiments/citemap_gate_v3.json
```

脚本需要 judge 配置（`.env` 中 `DEEPSEEK_API_KEY` 或 `CITEGUARD_JUDGE_BASE_URL`）；所有判断按提示词缓存，重复运行不重复计费。
