# 支持度标签的独立标注证据（LLM 盲标 / 共识）

> 结论先说：我们**没有人工标注**，也不把它写成人工标注。这里记录的是
> **三个独立 LLM 标注员（不同模型、不同 prompt、不看产品预测）** 的盲标结果，
> 用来回答两个问题：① 这套标签换一种问法还能不能复现；② 产品与“独立读者”的一致率是多少。

## 一、设置

- 数据：ClaimSupport-CN 100 条（构造标签：support 40 / partial 25 / contradict 15 / no_evidence 20）。
- 标注员：`deepseek-chat`、`deepseek-reasoner`、`qwen3-8b`（思考模式关闭）。
- 标注 prompt 与产品 prompt **不同**：只给四类定义 + 边界规则，不包含产品里的覆盖审计步骤；
  温度 0，单条独立调用。
- 标注是盲的：标注员看不到构造标签、看不到产品输出；三份结果各自落盘后才做汇总。
- 留出集：test 60 条用同样流程重跑一遍，检验是否过拟合 dev。
- 证据：`data/claimsupport_cn/llm_annotation_*.json`、`data/claimsupport_cn/llm_consensus*.json`；
  脚本：`scripts/llm_annotate_support.py`、`scripts/support_llm_consensus.py`。

## 二、主结果（100 条）

| 标注员 | 与构造标签一致率 | Cohen's κ |
|---|---|---|
| DeepSeek-Chat | 0.87 | 0.813 |
| DeepSeek-Reasoner | 0.98 | 0.957 |
| Qwen3-8B（本地） | 0.75 | 0.638 |
| 三模型多数投票 | 0.89 | 0.8425 |

- 两两一致率：D 与 R 0.85、D 与 Q 0.75、R 与 Q 0.74；多数投票与构造标签 89 条一致。
- 产品（v10 prompt + 审计 v1，托管路径）与多数投票的一致率 **0.90**，与构造标签 0.95。
- 产品判错 13 条，其中 3 条是产品与多数投票都错；其余 10 条两类：7 条“证据里有原句但没明说结论”，
  被产品判 partial；3 条构造标签本身可疑（证据是 claim 的逐字重复，人也会判 support）。

## 三、留出集（test 60 条）

| 标注员 | 一致率 | κ |
|---|---|---|
| DeepSeek-Chat | 0.8667 | 0.8086 |
| DeepSeek-Reasoner（59 条非空） | 0.9661 | 0.9525 |
| Qwen3-8B | 0.7333 | 0.6112 |
| 多数投票 | 0.8833 | 0.8335 |

- 产品与多数投票一致率 0.8833（macro-F1 0.8974），与构造标签 0.9333；
  该测试未参与任何 prompt/审计设计。
- 与 dev 相比没有明显下降，说明“产品比多数投票严”的倾向不是 dev 过拟合。

## 四、这些数字能证明什么、不能证明什么

**能证明：**
1. 标签不是只有一种问法能复现——三个模型独立标，多数投票与构造标签仍有 0.89 / κ 0.84；
2. 产品与独立多数投票的一致率约 0.90，且产品更严格（partial 边界）；
3. 留出集结果与 dev 接近，prompt 与审计没有严重过拟合。

**不能证明：**
1. **不能当作人工标注**，也不能报 human κ；评审若问“谁标的”，答案是“三个 LLM 独立盲标 + 多数投票”；
2. 三个模型共享训练语料与相似偏差，一致不等于正确；
3. 构造标签本身有噪声（逐字重复、背景句），上面的“一致率”上限被它限制。

## 五、如果以后补人工

`data/claimsupport_cn/human_review_40.csv` / `.xlsx` 是可选的 40 条盲评表，一个人 1 小时内可完成；
填完跑 `python scripts/check_human_labels.py <文件>` 即出人-构造、人-产品一致率与 κ。
没有这一步时，本文件就是标注证据的最终口径——**LLM 盲标，不是人工**。
