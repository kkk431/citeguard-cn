# 图表结论核验（可选能力）

> 一句话：把「图表 + 一句结论」交给开源的 Qwen2.5-VL-7B，判断结论是**被图表支持**、**与图表矛盾**，还是**图表信息不足**；粘贴论文正文/图注后，还会判断正文是否支持同一条结论。这是引文核验的补充，不替代逐条引文真实性检查。

## 它解决什么

论文里常见「见图 3，A 方法的准确率最高」这类结论。传统引文核验只查「这篇文献是否真实存在、摘要是否支持这句话」，看不到图里的数据。图表核验把截图和结论一起交给视觉模型，让它核对坐标轴、图例、数值与趋势。

输出三档：

| 判定 | 含义 | 建议动作 |
|---|---|---|
| `supported` | 图表与正文/图注都与结论一致 | 可保留 |
| `contradicted` | 图表或正文与结论矛盾（数值/年份/极值不符） | 必须改结论或改图 |
| `insufficient` | 图表信息不足，且正文没有覆盖该结论 | 人工复核，不要当作「支持」 |

正文上下文是**可选**的：不粘贴时只核对图表本身；粘贴后，模型会额外检查正文是否支持同一结论，并在理由里注明「正文一致 / 正文未覆盖 / 正文与图表冲突」。

## 模型与运行方式

- 模型：**Qwen2.5-VL-7B-Instruct**（Apache-2.0，来自 ModelScope/魔搭）。
- 硬件：单张 RTX 4090（24 GB），bf16，峰值显存约 **16.0–16.1 GB**；首次加载约 **8 秒**（之后常驻）。
- 服务：`scripts/local_vl_server.py` 起一个 OpenAI 兼容的 `/v1/chat/completions` 服务；产品只通过 HTTP 调用，CPU 主机不加载模型。
- 产品开关：`CITEGUARD_VL_ENDPOINT`（必填，指向服务）、`CITEGUARD_VL_MODEL`（默认 `qwen2.5-vl-7b`）、`CITEGUARD_VL_API_KEY`（可选）、`CITEGUARD_VL_TIMEOUT`（默认 60 秒）、`CITEGUARD_VL_MAX_FIGURE_MB`（默认 8 MB）。未配置时 `/figure` 页面只展示说明、不接受提交。
- 正文上下文：页面可选填写，最多 4000 字，随表单字段 `context` 提交；`PROMPT_VERSION = 2`。
  也可以上传论文 PDF 并指定页码（表单字段 `paper` + `page`，从 1 开始），服务端用 pdfplumber 取该页文字后拼进
  上下文；取不到文字（扫描页/文字层损坏）时返回明确错误，提示改为手动粘贴。PDF 只在服务进程的临时文件里处理，
  不落盘保存。接口返回里的 `context_source` 会标为 `pdf_page:N`。
- 隐私：图片与正文只在这一次请求里发给**你自己配置的** GPU 服务，不写入磁盘、不发给第三方；产品本身不保存图表。

## 实测结果

模型服务部署在实验室 4090 主机上。`scripts/eval_figure_prompt.py` 用同一套 50 条结论比较了三种口径：v1（仅图）、v2（仅图）、v2 + 正文/图注上下文。合成集的上下文用图题，真实集的上下文用图表所在 PDF 页的文字（截断 4000 字）。

| 口径 | 判定准确率 | 支持类召回 | 矛盾类召回 | 误报「矛盾」 | 平均延迟 |
|---|---|---|---|---|---|
| v1（仅图，历史） | 0.88 | 0.88 | 0.88 | 0 | 1.82 秒 |
| v2（仅图） | 0.90 | 0.88 | 0.92 | 0 | 2.43 秒 |
| **v2 + 上下文（产品默认）** | **0.94** | **0.92** | **0.96** | **0** | **2.56 秒** |

分数据集看（v2 + 上下文）：

| 数据 | 判定准确率 | 支持类 | 矛盾类 | 误报矛盾 |
|---|---|---|---|---|
| 合成控例（20 图 / 40 条） | **0.95**（38/40） | 18/20 | 20/20 | 0 |
| 真实论文图表（5 图 / 10 条） | **0.90**（9/10） | 5/5 | 4/5 | 0 |

上下文带来的增益主要来自合成集（图题里本来就写了极值）：36/40 → 38/40；真实集没有变化（9/10）。剩下的 3 个错误是：

- `synth_14` / `synth_18`：结论提到 2025 年，但图只画到 2024 年，模型判 `insufficient`（属于控例本身的边界，不是误报矛盾）；
- `real_03`：矛盾结论落在正文没覆盖的细节上，模型按规则退回 `insufficient`，建议人工复核。

### 为什么从 v1 换到 v2

v1 只要求「判断图与结论」，v2 把规则拆成两步：先判断图表，再在有上下文时判断正文；正文与图表冲突时以「矛盾」为准，正文没提到该结论则退回图表结论并注明「正文未覆盖」。v2 的附加规则在两个口径上都没有增加误报矛盾（三种口径的误报矛盾都是 0），并且矛盾类召回从 0.88 → 0.96，因此产品改用 v2；正文上下文默认留空，不影响只图核验。

## 复现

```bash
# 1) 生成合成控例（本地，需要 matplotlib）
python scripts/make_synth_figtest.py --n 20

# 2) 在 GPU 主机上起视觉服务（Qwen2.5-VL-7B，懒加载）
python scripts/local_vl_server.py --model /path/to/Qwen2.5-VL-7B-Instruct \
    --host 0.0.0.0 --port 8099

# 3) 复跑三种 prompt 口径（50 条，约 2–3 分钟）
python scripts/eval_figure_prompt.py
# 结果写到 data/experiments/figure_prompt_eval.json

# 4) 给产品打开能力
export CITEGUARD_VL_ENDPOINT=http://<gpu-host>:8099/v1
```

## 已知局限

- **输入是截图，不是 PDF 原图**：截图糊、字太小、图例被裁掉都会让模型读错；目前不做版面分析，只支持单张图表。
- **正文上下文：可粘贴，也可按页取，但不会自动找图注**：现在能上传 PDF 并指定页码自动取该页文字；仍需要用户知道图在哪一页，
  没有做「在图附近自动定位图注」的版面分析。扫描页取不到文字时会提示手动粘贴。
- **只校对「图 + 给定正文」**：不检查图表数据是否来自正文所述实验，也不做跨页、多图、跨章节推理。
- **中文与英文混排图表**偶尔会把年份/数值读错；`insufficient` 仍建议人工复核。
- **规模验证还小**：真实图表只有 10 条结论，结论方向明确，但不足以当作大样本精度承诺；对外汇报时应同时给出合成集的 40 条数字与这里的局限。
- 服务需要 GPU；产品主机（CPU）本身不能跑这个能力。
